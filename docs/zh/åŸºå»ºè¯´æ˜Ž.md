# Cat Nanny 基建说明（团队内部）

这份文档说明骨架里每个部分是做什么的、一次调用怎么走完、AWS 上要配什么，以及今天怎么把整条链路跑起来。
仓库的 README 是英文的，给评审看；这份是给团队自己看的。

## 1. 先说结论：比赛里接不上真的 Alexa+

Alexa+ 的 MCP Toolkit 和 `alexa-ai` CLI 目前只对少数合作伙伴开放，CLI 装在一个需要授权的私有仓库里。
比赛 FAQ 明确说参赛者没有办法接入真机，官方认可的做法是：**自己的 MCP 服务器 + 一个扮演 Alexa+ 的网页**。

所以整个项目由三块组成：

| 部分 | 位置 | 作用 |
|---|---|---|
| MCP 服务器 | `cat-nanny/server/` | 产品本体，部署在 Lambda 上。按 Alexa+ 文档里的真实请求格式写，以后有权限可以直接接真机 |
| Alexa+ 模拟器 | `cat-nanny/simulator/` | 网页版"Alexa"：听你说话 → 用 Bedrock 大模型决定调哪个工具 → 调 MCP 服务器 → 读出回复 → 在模拟的 Echo Show 屏幕上显示界面 |
| 规则包 | `cat-health-signals/` | 纯业务逻辑：追问、规律、危险信号、兽医摘要。不碰数据库、不碰网络 |

## 2. 一次调用怎么走完

以"Alexa, Mochi just threw up"为例：

```
浏览器（模拟器网页）
  │ 1. 语音识别成文字，连同"谁在说话"发给模拟器后端 POST /api/turn
  ▼
模拟器后端 simulator/sim/
  │ 2. 作为 MCP 客户端连上服务器：initialize 握手（协议 2025-11-25）→ tools/list
  │ 3. 把 8 个工具的描述和参数格式交给 Bedrock 大模型，连同这句话
  │ 4. 大模型决定：调用 log_health_event(cat="Mochi", type="vomit", reporter="Alex")
  ▼
API Gateway → Lambda：MCP 服务器 server/cat_nanny/
  │ 5. app.py 检查 Origin 和 Bearer token
  │ 6. tools.py：存事件到 DynamoDB → 取最近 60 天历史 → 调 cat-health-signals 的 assess()
  │ 7. 有 emergency / vet_today 级别的危险信号 → 存一条 alert，并通过 SNS 发邮件给家人
  │ 8. 返回 structuredContent：event_id、follow_up、red_flags、pending_alerts、assistant_guidance
  ▼
模拟器后端
  │ 9. 把结果交回大模型，大模型按 assistant_guidance 说成人话："Logged. Was it food, hairball, or liquid?"
  │ 10. 如果工具带界面（get_vet_summary），读取 ui:// 资源的 HTML
  ▼
浏览器
    11. 朗读回复；在 Echo Show 屏幕区域用沙箱 iframe 渲染界面（MCP Apps 协议）
```

用户回答"food"时，大模型带上上一步的 `event_id` 再调一次 `log_health_event`，服务器把细节补进同一条记录（方案 A：先存，后补）。

**家人提醒**的两条路：
- 即时：SNS 邮件（不需要注册手机号，每个家人点一次订阅确认邮件即可）。
- 对话里：alert 一直保持"未确认"，之后任何家人调用任何工具，返回值里都带 `pending_alerts`，大模型会顺带说出来；有人说"我们已经联系兽医了"，就调用 `acknowledge_alerts` 关掉它。

## 3. 每个文件是做什么的

### MCP 服务器 `server/cat_nanny/`

| 文件 | 作用 | 谁来改 |
|---|---|---|
| `app.py` | HTTP 入口：`/mcp`（MCP）和 `/healthz`。无状态 + 直接返回 JSON；Origin 校验（不合法回 403）；Bearer token（错误回 401，按 Alexa+ 文档不带 WWW-Authenticate） | 基建 |
| `handler.py` | Lambda 入口。服务器对象每个容器只建一次，每次调用套一个新的 HTTP 外壳（SDK 的会话管理器只能启动一次） | 基建 |
| `config.py` | 所有环境变量。默认内存存储 + 日志通知，所以本地不需要 AWS | 基建 |
| `store.py` | 存储接口 + 两个实现：`MemoryStore`（本地/测试）、`DynamoStore`（线上）。单表设计见文件顶部注释 | 基建 |
| `notify.py` | 通知接口：`LogNotifier`（本地）、`SnsNotifier`（线上邮件） | 基建 |
| `tools.py` | 8 个 MCP 工具。只做编排：校验 → 存取 → 调规则 → 组装返回。每个返回都带 `assistant_guidance` | 工具/对话的队友 |
| `ui/vet_summary.html` | 兽医摘要界面（MCP Apps），单文件、无外部依赖 | 界面的队友 |
| `demo_data.py` | Mochi 的 60 天示例数据，全部标记 `source="seed"` | 谁都可以 |

### 模拟器 `simulator/sim/`

| 文件 | 作用 |
|---|---|
| `mcp_bridge.py` | MCP 客户端：和 Alexa+ 一样用 initialize 握手、Streamable HTTP、Bearer token，并声明支持 MCP Apps |
| `agent.py` | "Alexa 的大脑"。`BedrockAgent` 用 Bedrock Converse API 做工具调用；`ScriptedAgent` 是离线模式，只认几句固定的话，用来不连 AWS 也能测通链路 |
| `app.py` | FastAPI：`/` 页面、`/api/turn` 一轮对话、`/api/config` |
| `static/index.html` | 网页：语音输入（Chrome/Edge）、朗读回复、切换"谁在说话"、Echo Show 屏幕、"Calls to the Cat Nanny MCP server"面板（演示视频里展示底层调用很有用） |

### 规则包 `cat-health-signals/`（规则定好后只改这里）

| 文件 | 要填什么 |
|---|---|
| `fields.py` | **字段定义**：每种事件的 details 有哪些 key、可选值。服务器会自动把它写进工具描述，大模型就知道要提取哪些信息 |
| `followup.py` | 每种事件的必填细节和对应追问（现在只有一条示例） |
| `redflags.py` | 危险信号规则，一条规则一个函数（现在只有一条示例：呕吐带血 → 今天看兽医） |
| `patterns.py` | 四条规律（现在返回空） |
| `models.py` | 数据结构（接口），改字段名要和服务器一起改 |

标着 `EXAMPLE ONLY` 的地方是为了测通链路放的占位，规则定好后替换掉。**改完规则不需要动服务器或基建的任何代码。**

## 4. AWS 上要配置什么（你负责的部分）

`infra/template.yaml`（SAM）一次建好以下资源：

| 资源 | 配置要点 |
|---|---|
| API Gateway HTTP API | 路由 `ANY /{proxy+}`，输出 `McpUrl`（…/mcp） |
| Lambda | Python 3.13、x86_64、512MB、29 秒超时；环境变量全部由模板注入 |
| DynamoDB | 单表，`pk` + `sk`（都是字符串），按需计费 |
| SNS 主题 | 邮件订阅 `AlertEmail`，部署后要去邮箱点确认 |
| CloudWatch 日志组 | 保留 14 天；每次工具调用写一行 JSON（工具名、参数、耗时、成功与否） |
| AWS Budgets | 当月费用超过预算 80% 发邮件 |
| IAM | Lambda 只能读写这张表、只能往这个主题发消息 |

模板外需要在控制台手动做的：
1. **Bedrock 模型**：在 Bedrock 控制台的模型目录里确认要用的模型可以调用（模型或推理配置文件的 ID 填到 `BEDROCK_MODEL_ID`），并确认本地 AWS 凭证有 `bedrock:InvokeModel` 权限。模拟器在本地跑，用的是你本机的 AWS 凭证。
2. **AWS CLI 和 SAM CLI**：本机安装并 `aws configure`。
3. **生成 token**：`openssl rand -hex 24`，写进 `.env` 的 `MCP_AUTH_TOKEN`。

## 5. 今天就跑起来的步骤

**第一步：本地跑通（不需要 AWS，约 10 分钟）**

```bash
# 两个仓库放在同一个父目录下
cd cat-nanny
cp .env.example .env
make setup        # 安装依赖，并以可编辑模式安装 ../cat-health-signals
make test         # 18 个测试：规则契约、工具、HTTP、Lambda 入口、DynamoDB（模拟）、模拟器全流程
make server       # 终端 1：MCP 服务器 http://localhost:8000/mcp，自带 Mochi 的示例数据
make sim          # 终端 2：打开 http://localhost:8080
```

在网页里依次输入（离线模式能识别）：
1. `Mochi just threw up` → 追问"Was it food, hairball, or liquid?"
2. `food, and there was some blood` → 第一句是"Please call your vet today."，终端 1 的日志里会出现 FAMILY NOTIFICATION
3. 把"Who's talking"切到 Sam，输入 `Did anyone give Mochi her medicine today?` → 回答末尾会转达 Alex 报告的情况
4. `Show Mochi's summary for the vet` → Echo Show 屏幕显示 30 天时间线

> Windows 用 PowerShell 的话，把 `make xxx` 换成 `.\scripts\dev.ps1 xxx`（setup / test / server / sim）。部署用的是 bash 脚本，`make deploy` 要在 WSL 或 Git Bash 里运行。

**第二步：接上 Bedrock（约 10 分钟）**

`.env` 里填 `BEDROCK_MODEL_ID` 和 `AWS_REGION`，重启 `make sim`。页面顶部会显示正在用的模型，这时说什么都能理解了。

**第三步：部署到 AWS（约 15 分钟）**

```bash
# .env 里填 AWS_REGION、ALERT_EMAIL、MCP_AUTH_TOKEN
make deploy                         # 打包 Lambda 并部署，最后打印各个输出
# 去邮箱确认 SNS 订阅
TABLE_NAME=<输出里的 TableName> make seed   # 可选：导入示例数据
# .env 里把 MCP_URL 改成输出里的 McpUrl，重启 make sim
make logs                           # 实时看工具调用日志
```

到这一步，"网页 → Bedrock → API Gateway → Lambda → DynamoDB / SNS"整条链路就全通了。

## 6. 从 Alexa+ 文档里查到、和我们相关的信息

| 主题 | 文档怎么说 | 我们怎么处理 |
|---|---|---|
| 传输 | 必须 Streamable HTTP，远程 HTTPS 地址 | 已满足 |
| 协议版本 | 概览写支持 2025-11-25，但示例握手用的是 2025-03-26 | 服务器支持 2024-11-05 到 2025-11-25 的握手；模拟器用 2025-11-25 |
| 用户身份 | 工具调用里**不传**用户、家庭、说话人或设备 ID；只有账号关联（OAuth）后才能识别用户 | 演示版固定一个 `HOUSEHOLD_ID`；`reporter` 由模拟器的"Who's talking"传入。README 里说明正式版用账号关联 |
| 认证 | Alexa+ 用 OAuth（client_credentials + 授权码 PKCE），未认证回 401 且不带 WWW-Authenticate | 演示用 Bearer token，401 行为已按文档实现。OAuth 留到有真机权限时再做 |
| MCP Apps | Alexa+ 从**工具结果**的 `_meta.ui.resourceUri` 读界面；MCP Apps 规范放在**工具定义**里 | 两处都写了 |
| 界面尺寸 | 设计基准 768×480，Echo Show 8/15 渲染为 1280×800；界面必须是单个 HTML、不依赖 localStorage | 兽医摘要按这个做的 |
| 延迟 | 建议往返 500ms 以内 | 热启动远低于此；Lambda 冷启动可能 1–2 秒，演示前先调用一次预热 |
| 主动通知 | 文档没有服务器推送到 Alexa app 的接口 | 用 SNS 邮件 + 对话内提醒代替 |
| 调用方式 | 支持按名字调用和隐式调用；工具描述要写清楚何时用、返回什么，不能夸大 | 每个工具的描述都按这个写了 |

## 7. 还需要团队确认的事

1. **字段定义**（`cat-health-signals/cat_health_signals/fields.py`）：现在是从设计文档抄的草稿，需要逐个确认每个字段都有规则在用。
2. **Bedrock 用哪个模型、哪个区域**：影响模拟器配置和成本。
3. **GitHub 组织名**：已定为 `Alexa-Cat-Nanny`，README 里的链接已经更新。
4. **许可证文件**：在 GitHub 建仓库时选 Apache-2.0，会自动生成 LICENSE，这里没有放。
